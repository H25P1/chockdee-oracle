## Lessons Learned

- **A scope-of-consent lesson learned from one incident should be checked against "what's the actual invariant here," not just "what category was the artifact."** After the `KBN_ERP_CONTEXT.md` rejection, the honest general rule was "any write to this external production financial system gets a preview before it's written" — not the narrower "shared docs need review, routine code doesn't." When a lesson gets re-triggered almost immediately in a superficially different shape, that's a signal the first formulation was too narrow, and it's worth restating it broader rather than writing a second, parallel lesson.
- **Before acting on an already-approved recommendation ("land it," "proceed"), re-verify the recommendation still holds against current reality** — a dry-run (`git cherry-pick --no-commit`, a diff, a test run) can reveal the approved action is now a no-op or has been overtaken by later changes, which is cheaper to discover before opening a PR than after.
- **When a global safety hook has no override (e.g. `git branch -D` blocked outright, no `--force`/confirmation escape hatch), stop and report rather than looking for a workaround** — the correct next step is telling the human what's blocked and why, not searching for an alternate command that achieves the same effect.
