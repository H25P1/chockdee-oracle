## Lessons Learned

- **When "proceed as recommended" includes editing a document that other AI agents/teammates read as their own source of truth, treat the document's actual content as a separate approval checkpoint from the general go-ahead to act.** Draft it, then show it, then write it — don't collapse "you're cleared to update the doc" into "you're cleared to write whatever I drafted" in one step, even when the drafting itself was careful and well-sourced.
- **`git branch -d`'s refusal is not proof a branch is unmerged — it only checks the branch against its own remote-tracking ref, not against the target branch (e.g. `main`).** Before treating a refusal as "real unlanded work" or a success as "definitely safe," verify with `git log --grep`/`git show` against the actual target branch, especially in repos that use squash-merge.
- **Before running any cleanup or investigation across multiple local branches in an unfamiliar repo, run `git worktree list` first.** A branch can look like an ordinary stale local branch in `git branch -a` (its `+` prefix marker is easy to miss) while actually being pinned to a live worktree elsewhere on disk — deleting or force-deleting it would orphan whatever's using that worktree.
- **When investigating a second/external repo mid-session from inside an Oracle's own working directory, expect the shell's cwd to reset to the Oracle's root between tool calls.** Use explicit absolute paths and `cd` on every command rather than assuming a `cd` persists — don't rely on relative paths carrying over.
