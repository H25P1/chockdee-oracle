## Lessons Learned

- **Cross-verify subagent output against a sibling agent's finding before committing, not just against the prompt's instructions.** Telling a subagent "don't invent content" is necessary but not sufficient — the strongest catch came from comparing two independent reports about the same repo, not from re-reading the fabricated one in isolation. When running parallel agents over the same target, treat contradictions between them as a required check, not a coincidence to notice if you happen to.
- **When a hook blocks direct push to a protected branch, establish the branch→push→PR→merge habit immediately after the first block** — don't re-negotiate the workflow on every subsequent commit. The first block is the signal to adopt the pattern for the rest of the session.
- **Before deleting a cached/cloned dependency that predates the current session, check whether something else (a global binary, another project) is live-symlinked to it** — "this looks like an old source clone" is not sufficient evidence that it's safe to remove; verify the negative (nothing depends on it) explicitly.
- **When exploring a codebase with parallel subagents, explicitly instruct each one to quote only what it personally read inside its assigned SOURCE_DIR** — without that constraint, an agent with broader filesystem access (e.g. sibling ghq clones sitting next to the target) may pull in content from an adjacent repo and misattribute it, producing plausible-looking but wrong documentation.
